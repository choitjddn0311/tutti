# CONTEXT GUIDE — Tutti

이 프로젝트의 세션·컨텍스트 운영 절차. 원본 공통 가이드: `01_CONTEXT_GUIDE.md`

## 신규 세션 시작
```text
CLAUDE.md와 docs/development/PROJECT.md, SESSION_HANDOFF.md를 읽고
현재 구현 상태, 진행 중인 작업, 미해결 문제와 다음 작업을 정리해줘.
문서에 없는 내용은 추측하지 말고, 아직 코드는 수정하지 마.
```

## 작업 시작
- `SESSION_HANDOFF.md`에서 현재 로드맵 단계와 다음 작업을 확인한다.
- 이번 작업의 범위와 완료 조건(DoD)을 먼저 정리한다.
- 같은 기능을 이어서 하고 세션 맥락이 충분하면 문서를 매번 전부 다시 읽지 않는다.

## 작업 중
- 현재 작업에 필요한 파일·코드 구간만 읽는다.
- 작업 범위가 바뀌거나 설계 변경이 필요하면 먼저 확인받는다.
- 설계 결정이 바뀌면 `PROJECT.md`에 반영한다.

## 작업 종료
기능 단위 작업이 끝나면 `CLAUDE.md`의 Git Workflow를 따른다: 브랜치 커밋 → PR → 코드 리뷰 → 사용자 승인 후 병합.

`SESSION_HANDOFF.md`를 갱신한다:
1. 완료한 작업 2. 변경 파일과 주요 변경 사항 3. 중요한 설계 결정
4. 테스트 항목과 결과 5. 남은 문제 6. 다음 작업

확인하지 않은 내용은 완료로 표시하지 않는다. 작은 작업을 같은 세션에서 이어간다면 매번 갱신하지 않아도 된다 — 기능 단위 완료, 작업 전환, 세션 종료 전에 갱신한다.

## /compact 와 /clear
| 상황 | 행동 |
|---|---|
| 같은 기능 계속 개발 | 세션 유지 |
| 대화가 길지만 맥락을 이어가야 함 | `/compact` |
| 다른 로드맵 단계·기능으로 전환 | HANDOFF 갱신 후 `/clear` |
| 작업 종료, 다음 세션에서 이어감 | HANDOFF 갱신 후 `/clear` |
| 컨텍스트 사용량 확인 | `/context` |

`/clear` 전에는 중요한 진행 상황이 문서에 저장됐는지 반드시 확인한다.

## 문서 역할 (중복 금지)
- `CLAUDE.md`: 항상 적용할 짧은 규칙 + 문서 위치
- `PROJECT.md`: 오래 유지되는 정보 (목적, 스택, 아키텍처, 데이터 모델, 설계 결정)
- `SESSION_HANDOFF.md`: 자주 바뀌는 현재 상태 (진행 상황, 로드맵 상태, 다음 작업)
